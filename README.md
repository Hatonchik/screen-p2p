# P2P трансляція екрана (WebRTC, 1080p / 60fps)

Просте рішення на WebRTC: сам відеопотік йде **напряму між двома
браузерами** (P2P), сервер потрібен лише для сигналінгу — щоб учасники
обмінялись технічними даними (SDP/ICE) і "знайшли" одне одного.

## Структура

```
screen-p2p/
├── server.js         # сигнальний сервер (Node.js + ws + express)
├── package.json
└── public/
    ├── index.html    # інтерфейс
    └── app.js         # логіка WebRTC
```

## Запуск

```bash
npm install
npm start
```

Сервер підніметься на `http://localhost:3000`.

1. Відкрий `http://localhost:3000` у двох вкладках/пристроях.
2. В обох введи однаковий **ID кімнати** та натисни «Приєднатись».
3. На одному з двох натисни «Почати трансляцію екрана» → обери екран/вікно.
4. У другій вкладці з'явиться відео.

Для трансляції між різними комп'ютерами в різних мережах сервер треба
задеплоїти на публічну адресу (наприклад, на VPS) — і відкривати вже
`http://<адреса_сервера>:3000`, а не localhost.

## Про якість 1080p / 60fps

- Реальний FPS і роздільна здатність залежать від того, **що саме**
  користувач обирає в діалозі захоплення (весь екран / вікно / вкладка) —
  захоплення вкладки браузера зазвичай дає найстабільніші 60fps, захоплення
  всього екрана — залежить від відеокарти й ОС.
- У коді явно виставлені `width/height/frameRate` constraints і бітрейт
  (`maxBitrate` ~8 Мбіт/с) — за потреби зменшуй/збільшуй залежно від каналу.
- Кодек обирає браузер автоматично (зазвичай VP8/VP9 або H.264,
  апаратно, якщо доступно).

## Важливо про NAT / TURN

STUN-сервер (`stun.l.google.com`) допомагає встановити P2P-з'єднання
через більшість домашніх роутерів. Але якщо один з учасників за
корпоративним фаєрволом або "жорстким" NAT, самого STUN може бути
недостатньо — з'єднання просто не встановиться. У такому разі потрібен
**TURN-сервер** (наприклад, власний [coturn](https://github.com/coturn/coturn)),
через який трафік піде вже не напряму, а транзитом.

## Безпека (продакшн)

Це мінімальний приклад для локального/довірчого використання. Для
публічного продакшену варто додати:
- HTTPS/WSS (браузери вимагають HTTPS для `getDisplayMedia` поза localhost),
- авторизацію/приватні кімнати (випадкові непередбачувані ID),
- обмеження на кількість кімнат і rate-limiting сигнального сервера.
